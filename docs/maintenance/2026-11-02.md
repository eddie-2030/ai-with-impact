## Main fixes

### Meeting Note Analyzer

Persistence helpers now flush pending rows within their existing transaction before callers use generated IDs. This gives new meetings valid parent IDs before child insertion and gives API results valid child IDs before serialization. Flushes do not commit, and rollback behavior remains intact.

Six PostgreSQL tests cover helper IDs and linkage, same-transaction updates, participant contributions, API analysis followed by retrieval, batch persistence, and rollback. Against the original production source, three tests failed and three passed. With the fix, all six pass.

Existing orphaned records are not repaired automatically. Repeated-analysis replacement/versioning and model-failure validation remain separate backlog items.

### Banking Fraud Detection

The transaction API now loads persisted account history and profile information before assessment. Creating a new account uses model defaults; assessing an existing account preserves its risk profile, status, and other attributes.

Shared timestamp handling normalizes ISO inputs to aware UTC values. Account history excludes other users, the current transaction ID, and future events. Matching and investigation windows are anchored to the assessed transaction's event time. Storage retains the existing timestamp-without-time-zone schema, using UTC-naive values; legacy naive timestamps are interpreted as UTC. API responses make the UTC offset explicit. Malformed request timestamps return HTTP 422 before assessment or writes.

The final suite includes a seeded real-database anomaly that produces the existing score of 71.5, returns a medium alert, persists its transaction/assessment/alert, and retrieves the result through the API. This verifies the existing policy plumbing; it does not validate fraud-detection effectiveness.

Risk weights, pattern scores, and severity thresholds are unchanged. High/critical reachability, calibration, recall, and false-alert rates require labeled data and remain open. Replay also uses the current stored account profile because historical profile snapshots are not available. Loading all prior account history remains a scaling concern for a future pass.
